# Luma knowledge map: Other Services

Generated by `php artisan luma:knowledge-map` from `app/Support/Luma/OtherServicesKnowledge.php`. Do not edit by hand: change the PHP file and regenerate.

Every node below becomes an intent named `id` through `php artisan chatbot:sync-defaults` (insert-only: an intent that already exists is never changed, so edits made in Admin > Chatbot are safe). The follow-up buttons are chips: tapping one sends its title as the next message, which reaches the child node. A node marked **handler** reads the signed-in customer's own data (guests get the general answer and a Log in button) or starts the guided flow. A node marked **contact card** also shows the shop's phone and email from Contact Settings. `{{tokens}}` are filled from config and Contact Settings, never typed in.

Tone: calm, never defensive, short sentences, plain words, "po" in Tagalog, apologise once, never blame the customer, never promise a refund or a date, never say "approved" or "guaranteed". See `docs/luma-tone-rules.md`.

### 14. Ambiguity (refund or cancel with no context)

No intent row: this is code (`App\Support\Luma\Disambiguation`). A bare **refund**, **cancel**, **payment**, **gcash**, **cash** or **bayad** with no context gets one question: *"Is this about an Other Services job (repair or labor) or a custom furniture order?"* with two chips. The answer is remembered for the conversation (30 minutes), so a follow-up like "and refund?" is not asked again. Other Services job -> the Other Services answer or the guided refund flow. Custom furniture order -> the existing `luma_cancel_refund` / `luma_payment_methods` answers, untouched.
